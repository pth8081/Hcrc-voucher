Lọc mã voucher theo tiền tố (tùy chọn)

So khớp chính xác từng ký tự (phân biệt hoa/thường) với phần bắt đầu của mã — VD tiền tố "E123" khớp mã "E1230001" nhưng KHÔNG khớp "E124...". Chỉ 1 trong 2 cách dưới đây có hiệu lực tại 1 thời điểm cho kết nối này — chọn cách đang áp dụng:

Để trống mục này mà vẫn chọn "Chỉ chấp nhận" sẽ bị từ chối khi lưu, vì nghĩa là chặn toàn bộ mã.

Chứng chỉ CA của đối tác (chỉ cần khi gọi HTTPS bị lỗi xác minh)

Bỏ qua mục này nếu Base URL ở trên dùng chứng chỉ HTTPS mua từ CA công khai (vd Let's Encrypt, DigiCert...) - trường hợp thông thường, đã hoạt động sẵn không cần làm gì thêm. Chỉ điền khi "Test kiểm tra"/"Test thu hồi" bị lỗi dạng xác minh chứng chỉ (vd UNABLE_TO_VERIFY_LEAF_SIGNATURE, SELF_SIGNED_CERT_IN_CHAIN) - lúc đó IT phía đối tác sẽ gửi cho bạn 1 file chứng chỉ CA công khai (.crt/.pem).

Đây là file công khai (không phải bí mật) do đối tác cung cấp để xác minh chính máy chủ của họ - an toàn khi tải/dán lên đây. Không dán nội dung bắt đầu bằng "-----BEGIN PRIVATE KEY-----" (private key) vào mục này.

Xác thực
Endpoint kiểm tra voucher (Check)

Dùng {code} trong path nếu chọn "Trong đường dẫn". VD: /api/vouchers/{code}/status

VD: nếu Core API trả về "0" nghĩa là chưa tiêu, thêm dòng: 0 -> UNUSED

Endpoint thu hồi voucher (Redeem)

Placeholder hỗ trợ: {code} {username} {locationsGroup} {locationsDetail} {transNum}

Test trực tiếp voucher thật

Dùng dữ liệu đang nhập trên form (chưa cần lưu) hoặc kết nối đã chọn ở trên để gọi thử Core API ngay, xem kết quả trả về có đúng như kỳ vọng không.

Test thu hồi sẽ GỌI THẬT sang Core API và có thể LÀM VOUCHER BỊ TIÊU thật sự, không thể hoàn tác. Chỉ test với voucher nội bộ/không quan trọng.
